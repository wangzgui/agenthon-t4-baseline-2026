## Findings established by source inspection
- The original S1.6 ZIP checksum and all six S1.6 model source files match its delivery record and original source commit.
- S1.7 removes all underscore fields from House row fields. This also removes _statement_fact; it is not separately exposed in the House payload. The validated source passage and financial proxy remain, but parsed financial metric/period/basis context is lost.
- S1.7 fusion returns zero weight on zero validation gain. Local practice fits show COT weight 0.383333 -> 0 and CPI weight 0.35 -> 0; auction weight 0.584574 is unchanged. These are effects on local fits, not explanations of hidden unit scores. A persistence model can regularize an uncertain House forecast without outperforming itself on validation.
- S1.7 adds arithmetic, decomposition, revision explanations and per-row reasons to the same 4000-output-token forecast call; truncation/missing rows and cognitive burden are plausible unmeasured risks.
- Quantity acceptance requires literal written units, metric phrases and periods. It is a precision-biased parser; rejected quantities provide no new arithmetic. Actual extraction yield is not measured because live House outputs are unavailable.
- Revision selection uses lexical overlap plus hard arithmetic gates; this can reject an economically sound paraphrase. It has not been validated for predictive selection quality.
- S1.7 reasoning has no direct Development reward. Co-generation can still affect predictions and request size. Its Final benefit has not been measured.

## S1.6 remaining issues
Task meaning remains heuristic; retrieval is one fixed pass, not a search triggered by missing target facts; the query loop can leave capacity unused. Structured facts do not systematically carry numeric scales and comparable observation periods. Prior quality is validated separately from the House blend. EPS transfer and calibration floors remain heuristic. Review is draft-dependent. Residuals calibrate the statistical component rather than the final predictor. Ranking forecasts can share a roster but still be assigned across separate batches. Runtime timeout/fallback behavior and actual model outputs need local observability. No submitted_reasons are emitted.
